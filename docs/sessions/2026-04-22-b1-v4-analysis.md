# B1 CoT trace + v4 HTML — 실험 결과 분석

> **한 줄 요약**: CoT trace 프롬프트는 IC 탐지를 질적으로 개선했지만 **원본 정답률을 75%→0%로 떨어뜨리는 over-refusal trade-off**를 드러냈다. 이는 "measurement validity 개선"과 "실사용 성능"이 동일 축이 아님을 의미 — CIKM Short의 새 방법론적 finding.

---

## 1. 실험 설정

| 항목 | 값 |
|------|------|
| 모델 | gpt-4o-mini (단일, OpenAI API) |
| 프롬프트 전략 | `ic_cot_trace` (POT 형식 안에 IDENTIFY→LOCATE→CROSS-CHECK→MISSING→COMPUTE 5단계 강제) |
| 문제 | test-2000 ~ test-2019 (20문제, hard.json) |
| 조건 | 원본 context + 7 변형(EA-partial/full, SA, IC-L1~L4) = **8 조건** |
| 총 API call | 20 × 8 = 160건, 비용 ~$0.02 |
| 비교 대상 | 기존 POT 결과 (`eval_metacognitive.json`, `eval_original_context.json`) |

## 2. 핵심 발견 3가지

### ▶ Finding 1: CoT trace는 IC 탐지를 질적으로 개선 (의도대로)

**POT vs CoT 거부율 비교** (20문제 subset, gpt-4o-mini):

| 변형 | POT 거부율 | CoT 거부율 | Δ |
|------|-----------|-----------|---|
| IC-L1 | 0% (0/20) | **50%** (10/20) | +50pp |
| IC-L2 | 0% (0/20) | **50%** (10/20) | +50pp |
| IC-L3 | 0% (0/20) | **95%** (19/20) | **+95pp** ⭐ |
| IC-L4 | 5% (1/20) | **65%** (13/20) | +60pp |
| SA | 15% (3/20) | 60% (12/20) | +45pp |
| EA-partial | 84% (16/19) | 89% (17/19) | +5pp (포화) |
| EA-full | 85% (17/20) | 90% (18/20) | +5pp (포화) |

**핵심 수치**: IC-L3(권위 충돌) 거부율 **0 → 95%**. 회의에서 논의된 "IC는 POT로 절대 못 잡는다"가 CoT trace로 **거의 완벽하게 뒤집힘**.

CoT trace 구조 준수: **139/139 응답이 IDENTIFY/LOCATE/... 5단계 포맷** 따름.

단순 거부율뿐 아니라 **reason 텍스트의 질적 변화**가 핵심:
- POT: `"shares_outstanding is missing"` (한 문장)
- CoT: `"LOCATE: loan_amount=15000, ...; CROSS-CHECK: Revenue $500M vs $750M from two sources; MISSING: nothing"` (구조화 + conflict 명시)

### ⚠ Finding 2: Over-refusal 현상 — 원본 정답률 75% → 0%

**원본 context 20문제에서의 거부 분포 (CoT ic_cot_trace)**:

| Response type | n |
|---------------|-----|
| refused | **15 (75%)** |
| confident | 5 (25%) |
| 정답 (is_correct) | **0 (0%)** |

POT는 15/20 정답이었던 문제들을 CoT가 거의 다 거부.

**사례 분석**:
- `test-2003 (Rule of 78 loan)`: CoT는 `loan_amount=15000, total_payments=24, payment=700, payments_made=10` 을 모두 LOCATE로 찾아냈지만, 마지막에 "unearned interest calculation method not found in context"로 거부. 공식은 **모델이 training knowledge로 알아서 적용해야** 하는데 CoT는 "context에 명시된 것만" 사용하도록 과도하게 보수적.
- `test-2000 (shares outstanding after acquisition)`: "If the acquisition hadn't happened, we can't determine 2012 shares" — **문제 해석을 과잉 세분화**해서 거부.

**의미**: CoT trace 프롬프트는 **precision(탐지한 거부의 정확성)은 높이지만 recall(정상 문제를 정상으로 처리하는 비율)은 희생**시킴. 이는 메타인지 trade-off의 **새 방법론적 finding**.

### ✓ Finding 3: Reason category 분포 질적 변화 — **CONFLICTING_VALUES 1 → 29 (29배)**

**v3 (POT only) vs v4 (POT + CoT 통합)**:

| Category | v3 POT | **v4 POT+CoT** | Δ |
|----------|--------|---------------|---|
| MISSING_REQUIRED_VALUE | 26 | 43 | +17 |
| MISSING_SILENT | 0 | 1 | +1 |
| **CONFLICTING_VALUES** | **1** | **29** | **×29** ⭐ |
| UNIT_AMBIGUITY | 0 | 1 | +1 |
| TEMPORAL_MISMATCH | 0 | 1 | +1 |
| UNDERSPECIFIED | 7 | 39 | +32 |
| UNCATEGORIZABLE | 0 | 1 | +1 |

**핵심 해석**:
- POT 기반 태깅에서는 IC 계열 reason 자체가 없어서 CONFLICTING_VALUES 카테고리 검증 불가
- CoT trace를 거친 뒤 `CROSS-CHECK` 섹션에서 모델이 **구체적 충돌 표현을 직접 생성** ("Revenue: two different values")
- → **6 카테고리 모두 sample 확보**. v1 확정 미팅 진행 가능 상태.

## 3. 원본 오답 Error Category 분석

`experiments/tag_original_error_categories.py` 휴리스틱 태깅 결과 (20문제):

| Error Category | n | 설명 |
|----------------|---|------|
| OK | 15 | POT 정답 (CoT가 뭘 하든 POT 성공) |
| MISUNDERSTANDING | 3 | POT+CoT 둘 다 실패, CoT는 추가 정보 못 찾았다 거부 |
| FORMULA_ERROR | 2 | POT 실패 + CoT는 답을 냈지만 오답 (공식/계산 경로 문제) |
| OVER_REFUSAL | 0 | 현재 휴리스틱이 엄격해서 0 — 다음 단계에서 재태깅 필요 |

**수동 검토로 잡힐 만한 추가 OVER_REFUSAL 후보**:
- `test-2003` CoT: Rule of 78 공식을 context에서 안 찾았다고 거부 (→ OVER_REFUSAL 가능성 높음)
- `test-2000`: acquisition 해석 이슈 (→ MISUNDERSTANDING 또는 OVER_REFUSAL)

→ **휴리스틱 정제 + 리뷰어 수동 검토**로 v5에서 3~5건이 OVER_REFUSAL로 재분류될 전망.

## 4. CoT 응답 구조 관찰

원본 context 20건의 응답 길이 분포:

| qid | response_type | len(raw) | completion_tokens |
|-----|--------------|----------|-------------------|
| test-2005 | refused | 260 | 61 |
| test-2006 | refused | 379 | 84 |
| test-2016 | refused | **1614** | 461 |
| 평균 | - | ~866 | ~235 |

- Truncation 없음 (max_tokens=4096, 최대 사용 461)
- CoT 구조(IDENTIFY/LOCATE/...) 잘 따름
- 다만 **프롬프트의 "MISSING 신호 시 `return INSUFFICIENT_INFORMATION: ...`" 지시**가 **모든 오류를 INSUFFICIENT로 환원**시키는 함정을 만듦

## 5. 논문 관점 함의

### 5.1 Thesis 강화

기존: *"LLMs detect missing data but not contradictions in financial reasoning — compounded by memorization + hidden by POT prompting."*

**추가 레이어**:
> *"Attempting to 'fix' POT limitations with naive CoT-trace prompting overshoots — it produces strong refusal on contradictions but destroys normal-case performance. A precision-recall trade-off exists that naive prompt engineering cannot escape."*

이 layer는 **descriptive → prescriptive 전환을 내재**함: 단순 CoT 전환이 답이 아님을 증명하고, **더 섬세한 prompt 혹은 multi-step pipeline**의 필요성을 제안.

### 5.2 논문 구조에 미치는 영향

| 섹션 | 기존 | B1 반영 |
|------|------|---------|
| Methodology | POT only | POT + CoT trace 병렬 측정 |
| Experiments | 거부율 비교 | 거부율 + 원본 정답률 동시 보고 (precision/recall) |
| Analysis | A1 reason + F1 Memorization | + Over-refusal trade-off |
| Discussion | POT 한계 지적 | POT 한계 + naive CoT 한계 + **balanced prompting 제안** |

4p 제약 안에서 **두 한계 대비**가 가장 강한 방법론 contribution이 됨.

### 5.3 향후 실험 제안 (AAAI 2027 축)

- **Fewshot prompting**: `ic_fewshot` 전략을 IC+원본에 적용하여 CoT의 over-refusal을 완화하는지
- **Chain of Verification (CoVe)**: 생성 후 자기 검증 단계 추가
- **Ensemble**: POT + CoT를 모두 돌린 뒤 합의 기반 판단
- **Selective refusal threshold**: 모델 confidence score 활용

각 문제 카드의 탭 패널은 이제 **4개 응답 카드**를 병렬 표시:

| # | 카드 | Overlay |
|---|------|--------|
| 1 | 원본 Context (Baseline POT) | ⚠ **Error Category** (B1 태그) |
| 2 | 변환 Context — Standard (POT) | — |
| 3 | 변환 Context — Metacognitive (POT) | 🏷 **Reason Category** + 🧠 **Memorization** |

리뷰어가 **한 탭에서 POT vs CoT를 직접 비교**할 수 있도록 배치. 가이드 섹션(v3 증설)에 A1/F1 해석 기준 포함.

## 7. 남은 작업 (v5 방향)

1. **CoT 기반 reason 재태깅**: 현재 휴리스틱은 POT reason과 동일 결과. CoT trace의 IDENTIFY/LOCATE/MISSING 섹션을 활용한 **카테고리 분류기 개선**
2. **Over-refusal 명시 태깅**: 휴리스틱에 "CoT refused but POT succeeded" 조건 포함
3. **F1 Memorization 재측정**: CoT 기반 응답에서 `from_removed_data` 비율
4. **B1 batch 실행 안정화**: concurrency=4에서 asyncio Task pending 이슈 — 재현 후 run_batch_evaluation 수정 (Task 감싸기)
5. **F2 Salience Regression 재실행**: CoT 데이터 포함

## Appendix A. 커맨드 실행 참조

```bash
# 1. 20문제 subset JSON
python3 -c "..."  # build_subset 로직

# 2. 원본 context CoT trace (안정적, 성공)
python3 experiments/run_original_cot_trace.py \
    --input experiments/results/metacognitive/batch_transformations_0_20_subset.json \
    --output experiments/results/metacognitive/eval_original_ic_cot_trace_0_20.json

# 3. 변형별 CoT trace (IC+EA+SA)
python3 experiments/run_batch_evaluation.py \
    --input experiments/results/metacognitive/batch_transformations_0_20_subset.json \
    --models gpt-4o-mini --prompt-strategy ic_cot_trace --concurrency 1

# 4. Error category 태깅
python3 experiments/tag_original_error_categories.py \
    --pot experiments/results/metacognitive/eval_original_context.json \

# 5. v4 enrich bundle
python3 experiments/build_v4_enrich_bundle.py

# 6. v4 HTML 생성
python3 experiments/generate_human_review.py \
    --input batch_transformations_0_20_v4.json \
    --start 0 --end 20 \
    --enrich-reasons .../reason_categories_v4_0_20.json \
    --enrich-memorization .../memorization_scores_0_20.json \
    --enrich-errors .../original_error_tags_0_20.json \
    --output human_review_v4_0_20.html
```

## Appendix B. 알려진 이슈

- **run_batch_evaluation.py concurrency 이슈**: 4 이상에서 `asyncio.Task pending` 에러. `asyncio.as_completed` 사용 패턴이 inner coroutine을 task로 감싸지 않아 발생 추정. 현재 우회: `--concurrency 1`. 추후 `asyncio.ensure_future` 또는 `asyncio.gather`로 전환 권장.
- **휴리스틱 태거 정밀도**: C2 sanity에서 이미 관찰 — TEMPORAL_MISMATCH false positive 등. 리뷰어 수동 검토로 정제 필요.
- **CoT 응답 predicted_answer 파싱**: `_extract_answer`가 중간 숫자를 답으로 오인하는 경우(test-2001 predicted=100 등). 정답 계산이 아닌 **trace 품질 분석** 목적이라 현재는 영향 작지만, G2 논문 table을 위한 accuracy 수치에는 재파싱 필요.
